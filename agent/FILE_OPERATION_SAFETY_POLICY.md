# Agent 文件操作安全规范

版本：1.4  
创建时间：2026-08-05 14:10（Asia/Shanghai）  
最后修改时间：2026-08-05 19:01（Asia/Shanghai）  
状态：强制执行

## 适用范围

本规范适用于此工作区内的所有 Agent、子 Agent、脚本、终端命令、文件 API 和外部工具。其他指令与本规范发生冲突时，必须采用对用户数据保护更严格的规则。

## 工作区边界：未经授权不得触碰外部路径

当前工作区根目录为 `D:\recovery\dilu_only_user`。该目录及其真实解析后的子路径是 Agent 默认唯一可以修改的文件范围。

1. 未经用户明确、书面允许，Agent 不得在当前工作目录以外创建、修改、覆盖、截断、重命名、移动、删除或以其他方式改变任何文件或目录。
2. 对工作区外目标的授权必须逐项写明绝对路径、具体操作和目的。诸如“清理 E 盘”“删除某个磁盘”“清理下载目录”或“处理所有匹配文件”的笼统表述，不构成授权。
3. 磁盘根目录、工作区父目录、系统目录、用户目录和任何工作区外的目录均不得作为批量、递归或通配符操作的目标。`E:\`、`D:\` 等卷根目录绝不能作为移除命令的目标。
4. 在每一次写入、移动或移除操作前，必须解析目标的规范绝对路径和真实路径，并验证其位于工作区根目录之下；当前 Shell 的工作目录、相对路径或字符串前缀均不能替代此核验。
5. 符号链接、联接点、快捷方式、挂载点或其他重定向对象不得被用来绕过工作区边界。其解析后指向工作区外时，必须停止并请求用户逐项授权。
6. 不得执行会枚举或影响多个磁盘、卷、用户目录或工作区外层级的清理脚本、递归命令、通配符命令或自动化任务。
7. 即使用户允许修改某个工作区外文件，该授权也不会放宽本规范中关于删除审查、逐项确认和“仅移入回收站”的要求。

## 文档变更时间记录

1. Agent 创建或修改任何文档时，必须在文档中记录具体时间，精确到分钟，格式为 `YYYY-MM-DD HH:mm`，例如 `2026-08-05 14:11`。
2. 除非用户明确指定其他时区，时间一律使用 `Asia/Shanghai`。
3. 对已有文档的每次实质性修改，必须追加可追溯的变更记录；不得只覆盖旧记录而不保留时间和变更摘要。
4. 删除审查文档必须同时记录创建时间、最后修改时间和用户批准时间（如适用）。

## 文档语言要求

1. Agent 新建或实质性修改的面向用户文档，标题、正文、表格、图注、变更记录和操作说明必须使用中文。
2. 论文题目、作者姓名、代码、文件路径、变量名、命令、标准名称、正式引文及其必要的技术术语可以保留原文；其余解释性内容必须以中文表达。
3. 既有由 Agent 生成但仍为英文的文档，在用户提出中文要求后，应在下一次涉及该文档的工作中转换为中文，并保留原始结论、数据、引用锚点和可追溯的变更时间。
4. 用户明确要求以其他语言交付时，以用户的该次明确要求为准。

## 1. 默认规则：不得自行删除

1. Agent 不得自行删除任何文件或目录。
2. 清理、重构、重新生成、测试准备、缓存移除，或主观认为某文件无用，均不构成删除授权。
3. 删除请求必须明确说明准确目标和用途。目标、范围、归属或影响不清楚时，必须停止并向用户澄清。
4. 用户授权仅适用于明确批准的目标，不得据此删除父目录、同级文件、关联产物、备份或回收站内容。
5. 临时文件、缓存、生成产物、日志、失败下载文件和重复文件也受本条保护，不存在自动例外。

## 2. 大于等于 10 MB 的文件：先审查、后操作

为避免单位歧义，本规范将大小达到 `10,000,000` 字节的文件视为需要审查的文件；文件系统显示的原始字节数必须记录在案。

在将任何达到该阈值的文件移入回收站前，Agent 必须：

1. 在 `agent/deletion-reviews/` 下创建一份 Markdown 审查文档。
2. 逐项列出拟处理文件的绝对路径、原始字节数、文件类型、拟移除原因，以及已知依赖或影响。
3. 说明目标的核验方式、是否存在备份或来源副本，以及如何从回收站恢复。
4. 将审查状态标为“等待用户批准”，并明确请求用户审阅和批准所列目标。
5. 等待用户作出明确批准。沉默、先前的笼统请求或推断出的意图均不构成批准。

一个批次中只要包含一个达到该阈值的文件，整个批次都必须先完成审查并获得批准。

## 3. 仅允许移入回收站

> **不可绕过的规则：任何获批的移除操作，唯一允许的结果是将已逐项核验的目标发送到操作系统回收站。不能证明会移入回收站的操作，一律不得执行。直接或永久删除在任何情况下均不允许。**

1. 只有在取得所需的明确授权和审查批准后，才可以将目标移入操作系统回收站。
2. Windows 上仅可使用能够明确指定“发送到回收站”的操作系统 API 或用户可见的 Shell 回收站操作；若无法确认该操作会发送到回收站，必须中止。
3. 禁止直接或永久删除。该禁令包括 PowerShell `Remove-Item` 和 `Clear-RecycleBin`、CMD `del` 和 `rd`、Unix `rm` 和 `rmdir`、`git clean`、安全擦除工具、破坏性文件 API，以及任何绕过回收站的命令或工具。
4. Agent 不得清空回收站、清除垃圾箱、执行安全擦除、格式化存储设备，或将工具配置为绕过恢复机制。
5. 若某工具无法将目标移入回收站，则不得用该工具执行移除操作。

## 3.1 防止跨盘误删的执行安全门

每一次获批的移入回收站操作都必须按以下顺序执行；任一项失败或结果不一致时，必须停止，不得尝试替代性删除命令：

1. 建立逐项清单，包含逻辑绝对路径、真实解析路径、所在卷、文件类型、原始字节数和预计目标数量。
2. 将该清单与用户批准的目标逐项比对。任何额外文件、目录、卷根目录、父目录、工作区外路径或无法解析的重定向对象都使操作失效。
3. 以字面量路径而非通配符或递归参数执行，并在调用前确认所用 API 或工具的结果为“发送到回收站”。
4. 操作后核验实际移入回收站的目标与已批准清单完全一致，并立即向用户报告结果和恢复位置。
5. 不得为了修复失败、权限错误、路径错误或工具不兼容而改用 `Remove-Item`、`del`、`rm`、递归删除或其他永久删除方式。

## 4. 批准前和操作前的必做核验

1. 显示并核验准确的绝对路径；不得依赖通配符、glob、相对路径歧义或 Shell 展开。
2. 核验目标类型、大小、父级位置，以及其是否为符号链接、联接点、快捷方式、挂载点或其他重定向对象。
3. 禁止以递归方式移除目录。目录中的每个文件必须单独列举并获得批准；不得把目录作为一个整体移入回收站。
4. 检查已知的仓库、应用、测试、构建和数据依赖，并在请求批准前报告实质性风险。
5. 记录用户批准、目标清单、移入回收站的方法和实际结果，保留简明审计记录。

## 5. 同等保护的破坏性操作

下列操作虽然不一定被称为“删除”，但同样可能造成数据丢失，必须遵循明确范围、用户授权和尽可能可恢复的原则：覆盖或截断文件、批量重命名或移动、重置仓库状态、替换生成输出、格式化磁盘、修改保留策略，以及会丢弃用户数据的安装或清理脚本。

## 6. 操作行为要求

1. 优先采用只读检查和可逆修改。
2. 不得将清理或移除隐藏在构建脚本、测试脚本、安装程序或实现步骤中。
3. 完成一次获批的移入回收站操作后，必须报告准确目标和恢复位置。
4. 存在任何不确定性时，必须保留数据、不执行移除，并询问用户下一步指示。

## 7. 删除审查文档模板

后续涉及达到阈值文件的请求，应在 `agent/deletion-reviews/` 下按以下结构建立审查文档：

```md
# 删除审查：<日期或任务名称>

创建时间：<YYYY-MM-DD HH:mm，Asia/Shanghai>
最后修改时间：<YYYY-MM-DD HH:mm，Asia/Shanghai>
状态：等待用户批准
请求原因：<为何需要移入回收站>

| 文件 | 绝对路径 | 原始大小（字节） | 类型 | 已知影响 | 备份/来源 | 恢复方式 |
| --- | --- | ---: | --- | --- | --- | --- |
| <名称> | <绝对路径> | <字节数> | <类型> | <影响> | <说明> | 从回收站恢复 |

核验说明：<路径、大小、链接和依赖检查结果>

请用户审阅并明确批准以上逐项列出的目标后，才可移入回收站。
```

## 8. 无自动豁免

本规范不存在自动豁免。任何例外都必须由用户以书面形式预先定义并明确批准；即使取得例外授权，也不得绕过“禁止直接永久删除”和“先移入回收站”的要求。

## 8.1 回收站后的最终删除仅限用户本人

> **终止边界：Agent 的文件移除权限在目标成功移入操作系统回收站时立即终止。此后任何永久删除、清空或清理操作只能由用户本人执行。Agent 不得执行、安排、自动化、调用工具实施，或以任何间接方式促成回收站内对象的最终删除。**

1. 无论用户使用“删除”“清理”“清空”等何种表述，Agent 的最大可执行范围都仅限将已逐项批准的工作区内目标移入回收站。
2. Agent 绝不清空回收站、删除回收站内的单个对象、配置自动清空或存储回收策略，也不使用任何命令、脚本、API 或第三方工具绕过该限制。
3. 即使用户明确要求永久删除，Agent 也只能完成移入回收站并停止；最终删除必须由用户本人在操作系统界面中自行审阅并执行。
4. 移入回收站后，Agent 必须报告准确目标路径、操作时间、回收站状态和恢复方式，并使用“已移入回收站”表述，不得称为“已删除”。
5. Git 取消跟踪、提交删除或重写远端版本历史属于版本控制状态变更，不等同于物理文件处置；此类操作必须明确说明其影响，且绝不能替代或掩盖回收站流程。
